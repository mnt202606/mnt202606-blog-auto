# 네이버 블로그 순위 하락 감지·진단·수정안 생성 시스템 설계

## 배경

머니테이블 네이버 블로그(mnt202606)의 검색 순위가 시간이 지나며 떨어지는 글들이 있다. 매일 아침 순위를 점검하고, 떨어진 키워드에 대해 상위 경쟁글과 비교해 원인을 진단한 뒤, 바로 붙여넣을 수 있는 보강 문구까지 자동으로 준비해 다음 세션에서 보고한다. 실제 글 수정·발행은 항상 사용자가 직접 한다 — 이 프로젝트의 표준 원칙([[naver_blog_autowrite]])과 동일하다.

## 핵심 제약

네이버 블로그 편집기는 **새 글 작성 화면에는 임시저장이 있지만, 이미 발행된 글의 수정 화면에는 임시저장이 없다** — 반영하려면 반드시 "발행" 버튼을 눌러야 한다. 이 시스템은 절대 자동 발행을 하지 않으므로, 기존 글에 수정안을 자동 삽입하는 기능 자체를 만들지 않는다. 진단과 보강 문구 작성까지만 자동화하고, 삽입·발행은 사용자가 수동으로 한다.

이 제약 덕분에 로그인 세션(storage_state.json)이 이 기능에는 전혀 필요 없다 — 순위 확인과 경쟁글 열람은 모두 로그인 없는 공개 페이지 접근만으로 가능하다.

## 아키텍처

```
naver_autowrite/rank_monitor/
├── published_posts.json   # {topic: {title, url, logNo}} - 발행 확인된 글 매핑
├── keywords.json          # {keyword: {topic, addedDate}} - 추적 대상 키워드
├── rank_history.json      # {date: {keyword: {rank, url}}} - 일별 순위 기록
├── fixes/                 # 하락 감지 시 생성되는 진단+보강문구 파일
│   └── fix_<keyword>_<date>.md
├── scan_published.js      # 블로그 공개 목록 스캔 → published_posts.json 갱신
├── extract_keywords.js    # published_posts.json 제목에서 키워드 추출 → keywords.json 갱신
└── check_ranks.js         # 키워드별 순위 확인 → rank_history.json 기록 + 하락 목록 반환
```

### 1. 발행글 자동 파악 (`scan_published.js`)

- `blog.naver.com/mnt202606` (공개, 로그인 불필요)을 Playwright로 스캔해 전체 글 목록(제목, URL, logNo)을 가져온다.
- `naver_autowrite/content_*.json`의 제목들과 매칭한다: 제목에서 조사·해시태그성 수식어를 뗀 핵심 명사구 토큰들을 뽑아, 발행글 제목과 60% 이상 토큰이 겹치면 같은 글로 판단한다(제목을 나중에 바꿔 발행해도 핵심 키워드는 남아있다는 전제 — 실제로 청약통장전환마감 건도 제목을 후킹형으로 바꿨지만 "청약통장", "갈아타" 등 핵심 토큰은 유지됐다).
- 매칭된 것만 `published_posts.json`에 기록한다. 매칭 안 되는 초안(아직 미발행)은 순위 추적 대상에서 제외한다. 토큰 겹침이 애매한 경우(40~60%)는 잘못 매칭하느니 건너뛴다 — 재현율보다 정확도를 우선한다.

### 2. 키워드 추출 (`extract_keywords.js`)

- `published_posts.json`의 각 제목에서 핵심 키워드 2~4개를 뽑는다. 조사·불용어(생활정보, 총정리, 2026년 등 지나치게 일반적인 단어)는 제외하고, 정책명·제도명·구체적 명사구 위주로 뽑는다.
- 이미 `keywords.json`에 있는 키워드는 건너뛰고 새 글의 키워드만 추가한다.

### 3. 순위 확인 (`check_ranks.js`)

- 각 키워드로 `m.search.naver.com/search.naver?ssc=tab.m_blog.all&query=<키워드>` 모바일 검색 결과를 조회한다(로그인 불필요, 실제 Chrome + Playwright).
- 블로그 결과 링크들을 순서대로 파싱해 `mnt202606`의 글이 몇 번째인지 찾는다. 30위 밖이면 "권외"로 기록한다.
- 오늘 날짜로 `rank_history.json`에 `{keyword: {rank, url}}` 기록.
- 직전 기록 날짜와 비교해 순위가 나빠진 키워드 목록을 반환한다(권외→진입 등 반대 방향은 하락으로 안 침).

### 4. 진단 + 보강 문구 생성

하락 키워드마다:
- 우리 글 전문(모바일 공개 페이지에서 읽기)과 현재 상위 3개 글의 제목+도입부를 수집한다.
- 별도 API 호출 없이 이 세션(클라우드 루틴을 실행 중인 Claude)이 직접 다음을 작성한다:
  - **진단** (3줄 이내): 상위 글과 실제로 다른 점만, 추측 없이.
  - **보강 문구**: 기존 글 톤 유지하며 부족한 부분만 채우는 문단. 삽입 위치를 특정할 수 있도록 "이 문장 뒤에 삽입하세요" 형태로 기존 글의 실제 문장(앵커)을 함께 제시한다.
- `fixes/fix_<keyword>_<날짜>.md`로 저장.

### 5. 보고

- 기존 "아침 8시 네이버 블로그·블랙키위 키워드 리서치" 클라우드 루틴([[daily_naver_blog_draft_routine]])에 이 순위 점검을 추가 단계로 합친다 — 별도의 새 8시 루틴을 만들지 않는다.
- 다음 세션 시작 시, 하락한 키워드 목록과 각각의 진단·보강 문구를 채팅에 바로 보여준다(파일 경로만 던지지 않고 내용을 인라인으로).
- 하락이 없으면 조용히 넘어간다(매일 "하락 없음" 보고로 채팅을 채우지 않는다).

## 오류 처리

- 검색 결과에 우리 글이 아예 안 잡히면(권외) 그 키워드는 "권외"로만 기록하고 진단은 만들지 않는다(비교할 우리 글의 현재 순위가 없으므로).
- 경쟁글 읽기가 실패하면(비공개 전환, 삭제 등) 해당 경쟁글은 건너뛰고 나머지로 진단한다.
- `published_posts.json` 매칭에 실패하는 초안이 있어도 에러 없이 그냥 추적 대상에서 제외한다.

## 범위 제외 (이번엔 안 함)

- 기존 글에 자동 삽입하는 기능 (`rank_apply.js` 상당) — 위 제약 때문에 처음부터 제외.
- 카카오톡/이메일 알림 — 다음 세션 채팅 보고로 충분하다는 결정.
- 순위 하락 원인의 정량적 스코어링 — 진단은 정성적 3줄 요약으로 충분.
